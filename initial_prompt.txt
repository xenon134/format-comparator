Generate a python project Format Compare Visual that takes in an input image, opens up a Tkinter window with the following UI: a file size slider on top, ranging from 0 to the file size of the input, and then a grid. This all will be handled by main.py. The grid will be populated by that input image rendered by different codecs and formats to match the file size given in the slider.

In another file write definitions for all the common image formats like PNG, JPEG, WEBP, etc. and their parameters, so like quality=[0, 100] for JPEG, optimize=True/False for PNG, etc. These definitions should follow a standard format and structure so that new formats can be plugged in easily.

In another file, write code that takes a particular format, and finds the optimal configuration of its options + scale to get the file size that's closest to the file size selected in the slider. What's scale you ask? Well let's take JPEG for example. PIL's save accept the following options for JPEG: quality, optimize, progressive, dpi, icc_profile, exif, keep_rgb, subsampling, restart_marker_blocks, restart_marker_rows, qtables, streamtype and comment. Out of these, the ones that are relevant to us are quality, optimize  and subsampling. optimize=True will obviously produce a better file size than optimize=False with no loss in quality so we won't consider that. So the format for JPEG will expose these parameters - quality ∈ [1, 95] and subsampling ∈ {'4:2:0', '4:2:2', '4:4:4'}. In addition, every format will also have a `scale` parameter ∈ (0, 1] which represents the factor by which the image will be scaled by (img.resize(img.width/scale, img.height/scale)) before being fed to the codec. The optimizer will find the combination that produces the closest file size that's lesser than or equal to the selected file size.

So say the user inputs 2.5 KB. Immediately the optimizers will get to work (all in parallel). Naturally, efficient codecs like WEBP will come up with a much better quality image while inefficient ones like PNG will have to aggressively throw away data (since PNG itself has no tunable parameters (parameters like optimize will simply be set to True, nothing to tune there), the only parameter that will get optimized is resolution scale)

If there's only one parameter (like with PNG, or lossless -WEBP) the optimizer can do simple binary search. Make sure you use an efficient optimizing algorithm for higher parameter counts. Use multithreading/multiprocessing where applicable. Don't be afraid to modularize. modularization is our friend.
